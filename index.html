À propos

Avant de coder mon premier pipeline, j'analysais des fibres d'amiante à la microscopie électronique. Projets

Projet phare

RetailFlow, plateforme data e-commerce

De l'ingestion multi-source à la restitution décisionnelle, un pipeline orchestré de bout en bout

Contexte et problématique

RetailFlow reproduit la chaîne de valeur data d'une entreprise e-commerce : transformer des données brutes et dispersées en indicateurs fiables, exploitables par les équipes métier, sans intervention manuelle une fois le pipeline lancé. L'objectif du projet : construire une architecture data telle qu'on la retrouve en entreprise, avec orchestration, tests de qualité, supervision et restitution BI, pas un notebook isolé qui tourne une seule fois.

Architecture et pipeline

Pipeline de bout en bout :

  1.  Ingestion multi-source
  2. OrchestrationAirflow
  3. EntrepôtPostgreSQL
  4. Transformationdbt
  5. ExpositionFastAPI
  6. Supervision et restitutionPrometheus / Grafana / Metabase
  • Ingestion : DAG Airflow retailflow_pipeline de 16 tâches, qui ingère automatiquement 4 sources de données distinctes et valide leur qualité avant de charger l'entrepôt.
  • Transformation : modélisation en couches avec dbt (staging puis marts), tests de qualité dbt intégrés directement au DAG.
  • Entrepôt : PostgreSQL, interrogé nativement par Metabase pour la restitution décisionnelle.
  • API : FastAPI exposant les données clients, ventes et stock, documentée automatiquement via Swagger.
  • Orchestration : exécutions planifiées automatiquement en plus des déclenchements manuels, historisées sur plusieurs jours : le pipeline tourne en continu, pas à la demande.
  • Infrastructure : Docker Compose multi-services (8 services : orchestrateur, API, entrepôt, BI, monitoring).
  • Observabilité : Prometheus et Grafana supervisent à la fois la santé du pipeline (fraîcheur des données, résultats des tests dbt, volumes et qualité par table) et l'API en production (trafic par route, latence P50/P95/P99, erreurs HTTP, ressources).
  • BI : dashboard Metabase construit sur les marts dbt : chiffre d'affaires, répartition géographique et par catégorie, segmentation clients, santé du stock visualisée via une jauge à seuils.

Qualité et DevOps

  • CI/CD : pipeline GitHub Actions déclenché à chaque push (build, vérifications).
  • Conteneurisation : l'ensemble des services est décrit dans un Docker Compose unique, environnement reproductible en une commande.
  • Qualité des données : validation automatique intégrée au DAG avant chargement de l'entrepôt, complétée par les tests dbt sur les modèles.
  • Documentation : README technique détaillé (architecture, stack, liste des services et ports, captures d'écran commentées).

Analyse de sentiment client

Pipeline d'analyse de satisfaction client

ShowroomPrivé : du scraping au dashboard décisionnel

Contexte et problématique

ShowroomPrivé accumule des milliers d'avis clients sur Trustpilot, impossible à exploiter manuellement à cette échelle. L'objectif : automatiser leur collecte, détecter automatiquement les sentiments négatifs et fournir aux équipes métier un tableau de bord décisionnel actualisé en continu. Du scraping à l'alerte Prometheus, chaque étape du pipeline est orchestrée, testée et monitorée.

Architecture et pipeline ETL

Pipeline de bout en bout :

  1. MongoDB
  2. Airflow
  3. MySQL
  4. FastAPI
  5. Prometheus / Grafana
  • Ingestion : scraping de 20 259 avis via BeautifulSoup, migration des données brutes de MongoDB vers MySQL orchestrée par Airflow (98,7 % d'intégrité).
  • Modélisation : schéma relationnel optimisé, scripts de transformation et tests de qualité des données.
  • Machine learning : analyse de sentiments avec TF-IDF, régression logistique, Random Forest, SVM et CamemBERT. Réentraînement automatique, F1-score de 0,92.
  • API REST : FastAPI avec documentation Swagger, endpoints /predict, /stats et health check, latence inférieure à 200 ms.
  • Orchestration : DAG Airflow à 7 tâches (scraping, nettoyage, agrégation, stockage, reporting, alertes, ML).
  • Infrastructure : Docker Compose multi-services (MySQL, MongoDB, Airflow, API, monitoring).
  • Observabilité : stack Prometheus, Grafana et StatsD pour métriques temps réel et alerting automatique.

Qualité et DevOps

  • Architecture modulaire : src/ingestion, src/transform, src/utils. Chaque module est indépendant et testable.
  • Tests et formatage : Black, Flake8, pytest avec 87 % de couverture.
  • CI/CD : GitHub Actions pour build, tests et déploiement en staging.
  • Sauvegarde : scripts automatisés mysqldump et mongodump.
  • Documentation : README technique complet, ERD, diagrammes d'architecture, OpenAPI/Swagger.
