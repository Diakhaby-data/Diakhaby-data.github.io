À propos

Du microscope au pipeline : la même discipline, appliquée à un autre matériau.

Depuis février 2022, j'analyse des matériaux de construction et des filtres d'air pour y détecter des fibres d'amiante, en microscopie optique et électronique, sous accréditation ISO. Environ 1 100 échantillons par mois, chacun suivi de la réception jusqu'au rapport. C'est là que j'ai compris ce qu'un pipeline de données exige aussi : des étapes reproductibles, un contrôle à chaque passage et des résultats dont on peut répondre.

En 2025, j'ai obtenu le certificat Data Engineer de Mines Paris PSL Executive Education, en partenariat avec DataScientest. J'ai depuis construit deux plateformes complètes. RetailFlow orchestre avec Airflow et dbt l'ingestion, la transformation et la supervision d'une plateforme data e-commerce, jusqu'à l'API et aux dashboards Grafana et Metabase. Le second projet analyse la satisfaction client de ShowroomPrivé, du scraping des avis jusqu'à un modèle NLP exposé par API.

Je cherche un CDI de Data Engineer dans une équipe qui traite la qualité des données comme un sujet d'ingénierie, et non comme une vérification de fin de chaîne.

Projet principal

RetailFlow, plateforme data e-commerce

De l'ingestion multi-source à la restitution décisionnelle, un pipeline orchestré de bout en bout.

Code sur GitHub

RetailFlow reproduit la chaîne de valeur data d'une entreprise e-commerce : transformer des données brutes et dispersées en indicateurs fiables pour les équipes métier, sans intervention manuelle une fois le pipeline lancé. L'objectif était de construire une architecture comparable à celles des équipes data en entreprise, avec orchestration, tests de qualité, supervision et restitution BI, plutôt qu'un notebook exécuté une seule fois.

  1. Ingestion4 sources
  2. OrchestrationAirflow
  3. EntrepôtPostgreSQL
  4. Transformationdbt
  5. ExpositionFastAPI
  6. Supervision et BIGrafana, Metabase

Architecture

  • Ingestion : le DAG Airflow retailflow_pipeline (16 tâches) ingère 4 sources distinctes et valide leur qualité avant de charger l'entrepôt.
  • Transformation : modélisation en couches avec dbt (staging, puis marts), tests dbt intégrés au DAG.
  • Entrepôt : PostgreSQL, interrogé directement par Metabase.
  • API : FastAPI expose les données clients, ventes et stock, documentées automatiquement via Swagger.
  • Orchestration : exécutions planifiées en plus des déclenchements manuels, historisées sur plusieurs jours.
  • Infrastructure : Docker Compose, 8 services (orchestrateur, API, entrepôt, BI, monitoring).
  • Observabilité : Prometheus et Grafana suivent la santé du pipeline (fraîcheur des données, tests dbt, volumes et qualité par table) et l'API (trafic par route, latence P50, P95 et P99, erreurs HTTP, ressources).
  • BI : dashboard Metabase sur les marts dbt : chiffre d'affaires, répartition géographique et par catégorie, segmentation clients, santé du stock par jauge à seuils.
  • CI/CD : workflow GitHub Actions déclenché à chaque push (build et vérifications).

Analyse de satisfaction client ShowroomPrivé

Du scraping des avis Trustpilot au dashboard de suivi, avec un modèle de sentiment exposé par API.

Code sur GitHub

ShowroomPrivé accumule des milliers d'avis clients sur Trustpilot, impossibles à lire un par un. Le pipeline automatise leur collecte, détecte les avis négatifs et alimente un tableau de bord actualisé en continu pour les équipes métier. Chaque étape, du scraping à l'alerte Prometheus, est orchestrée, testée et supervisée.

  1. CollecteScraping
  2. Données brutesMongoDB
  3. OrchestrationAirflow
  4. Base relationnelleMySQL
  5. Modèle et APINLP, FastAPI
  6. SupervisionPrometheus, Grafana

Architecture

  • Ingestion : 20 259 avis collectés avec BeautifulSoup, migration de MongoDB vers MySQL orchestrée par Airflow (98,7 % d'intégrité).
  • Modélisation : schéma relationnel optimisé, scripts de transformation et tests de qualité des données.
  • Machine learning : TF-IDF, régression logistique, Random Forest, SVM et CamemBERT comparés ; réentraînement automatique.
  • API REST : FastAPI, endpoints /predict, /stats et health check, documentation Swagger.
  • Orchestration : DAG de 7 tâches : scraping, nettoyage, agrégation, stockage, reporting, alertes, ML.
  • Infrastructure : Docker Compose multi-services (MySQL, MongoDB, Airflow, API, monitoring).
  • Observabilité : Prometheus, Grafana et StatsD pour les métriques en temps réel et l'alerting.
  • Qualité du code : modules src/ingestion, src/transform, src/utils testables séparément ; Black, Flake8, pytest.
  • CI/CD et sauvegarde : GitHub Actions (build, tests, déploiement en staging), sauvegardes mysqldump et mongodump.
